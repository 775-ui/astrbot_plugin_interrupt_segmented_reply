# astrbot_plugin_stoprushingiamtyping

# 🤖 分段回复可打断

> **复刻 AstrBot 原生分段回复 · 支持用户插话打断 · 智能符号处理 · AI 感知打断，本插件在AI指导中创作**

在 AstrBot 中，机器人在分段回复长文本时，如果用户在此期间发送了新消息，本插件会**立即停止补发剩余分段**，即"打断机器人的上一条答复"。同时支持符号过滤、空括号清理、AI 上下文感知等增强功能。

---

## ✨ 功能特性

### 🎯 核心功能

| 功能 | 说明 |
|---|---|
| 🛑 **分段回复可打断** | 用户插话后立即停止补发剩余分段 |
| ⏱️ **复刻原生分段逻辑** | 完全参照 AstrBot 原生分段回复实现，支持 `words` / `regex` 两种分段模式 |
| 🔔 **单次打断提示** | 同一轮分段只提示一次"已打断～"，不会重复刷屏 |
| 🧠 **AI 感知打断** | 打断时向上下文注入标记，让 AI 知道自己没说完，且完整内容仍在上下文中 |

### 🎨 增强功能

| 功能 | 说明 |
|---|---|
| 🔣 **句末符号保留** | 分段后句末标点（`。！？…` 等）完整保留在段尾 |
| 📎 **闭合符号粘连** | `」』》〉】` 等闭合符号自动粘在前一段末尾，绝不单独占行 |
| 🧹 **自定义符号过滤** | 通过 `content_cleanup_rule` 正则过滤每段中的无用内容 |
| 🈳 **空括号自动清除** | 自动删除无内容的括号对（如 `《》` `[]` `『』` 等） |
| 🚫 **通知事件过滤** | "正在输入"等 QQ 通知事件不会误触发打断 |

## 📦 安装

### 方式一：通过 AstrBot WebUI 安装插件（推荐）

打开 AstrBot WebUI → **插件管理** → **安装插件**，输入本仓库地址：

```
https://github.com/你的用户名/astrbot_plugin_interrupt_segmented_reply
```

点击安装即可。

### 方式二：手动安装

将整个仓库克隆到 AstrBot 的插件目录：

```bash
cd /root/AstrBot/data/plugins
git clone https://github.com/你的用户名/astrbot_plugin_interrupt_segmented_reply.git
```

> 🚨 **重要**：安装后请关闭 AstrBot 平台内置的分段回复（`segmented_reply.enable = false`），避免双重分段。

## ⚙️ 配置说明

在 WebUI → 插件页 → 本插件 → 配置面板中，可调整以下参数：

### 分段设置

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 是否启用本插件 |
| `only_llm_result` | bool | `true` | 仅对 LLM 生成的回复进行分段 |
| `words_count_threshold` | int | `150` | 回复字数**超过**此值时不分段，直接整条发送 |
| `split_mode` | string | `words` | 分段模式：`words`=分段词列表，`regex`=正则 |
| `regex` | string | `.*?[。？！~…]+|.+$` | 分段正则（`regex` 模式） |
| `split_words` | string | `。,？,！,~,…` | 分段词列表（`words` 模式），逗号分隔 |

### 间隔设置

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `interval_method` | string | `random` | 分段间隔方法：`random` 或 `log` |
| `interval` | string | `3.5,4.5` | `random` 模式的间隔范围（秒），格式：`最小,最大` |
| `log_base` | float | `2.6` | `log` 模式的对数基底 |

### 打断设置

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `interrupt_enabled` | bool | `true` | 是否启用用户新消息打断分段回复 |
| `interrupt_scope` | string | `session` | 打断范围：`session`=同会话任何人；`sender`=仅被回复的用户 |
| `notify_interrupted` | bool | `true` | 打断时是否发送提示（同一轮只提示一次） |
| `interrupt_notice` | string | `已打断～` | 打断提示文案 |

### AI 感知设置

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `notify_model` | bool | `true` | 打断后是否向 AI 上下文注入打断标记 |
| `interrupt_model_mark` | string | `（此条回复被用户打断了…）` | 注入上下文的打断标记文案 |

### 符号处理设置

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `content_cleanup_rule` | string | `""` | 自定义符号过滤正则，留空不过滤 |
| `remove_empty_brackets` | bool | `true` | 是否自动过滤无内容的空括号对 |
| `empty_brackets` | string | `《》,[],『』,［］,（）,【】,「」` | 空括号对列表，逗号分隔 |

## 🎯 使用效果

### 打断回复

```
用户：帮我写一篇关于人工智能的文章
AI：「好的，人工智能是当前科技……（第1段）
      ……领域最热门的话题之一……（第2段）
用户：等等，具体说说深度学习
AI：「已打断～」                      ← 插件秒回
     （几秒后）
     深度学习是机器学习的一个分支……  ← AI 对打断消息的正常回复
```

### 符号处理

| 输入 | 输出 |
|---|---|
| `这是《》测试` | `这是测试`（空括号被过滤） |
| `(000000000)(1111111)` | `(000000000)`<br>`(1111111)`（括号完整保留） |
| `他说：『好的』。然后走开` | `他说：『好的』。`<br>`然后走开`（闭合符号不孤立） |

### AI 感知打断

打断后，AI 会知道自己的上一条回复未发送完整，且完整内容仍保留在上下文中——它可以在后续对话中自然地承接话题：

```
用户：你还记得刚才我说打断你的时候，你想说什么吗？
AI：记得，刚才我说到人工智能的伦理挑战，主要包括隐私保护、
     算法偏见和责任归属三个方面，我继续讲……
```

## 🤝 兼容性

- **AstrBot 版本**：`>=4.16,<5`
- **适配平台**：QQ（OneBot v11 / NapCat / LLOneBot 等）、其他 AstrBot 支持的消息平台
- **已知冲突**：无。若同时使用消息聚合类插件（如 `astrbot_plugin_smoothchat`），建议将聚合插件的 `flush_timeout` 调小（如 `1.5s`），以提高打断响应速度
